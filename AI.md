# BCSH AI Policy

AI-assisted development is allowed in BCSH.

AI can be used to:

- Write code
- Suggest changes
- Find bugs
- Explain code
- Write tests
- Help with development

However, **the person submitting the code is fully responsible for it**.

## Human Review Is Required

All AI-generated or AI-assisted code must be reviewed by a human before it is submitted.

Do not blindly accept AI-generated code.

The person submitting the change must understand what the code does and should be able to explain it.

AI output is not considered automatically correct.

## Human Testing Is Required

All AI-generated or AI-assisted code must be tested by a human before it is considered complete.

Automated tests are useful, but they do not replace human testing.

The contributor should actually use and test the affected functionality when practical.

For example, if AI changes `cd`, the contributor should actually run BCSH and test `cd`.

## Full Responsibility

The BCSH project owner and contributors are responsible for the code they submit, regardless of whether AI was used to create it.

Using AI does not transfer responsibility to the AI provider.

If AI generates broken, insecure, unnecessary, or incorrect code, it is still the responsibility of the person who submitted it to identify and fix the problem.

## Human-Written User-Facing Content

Anything user-facing outside of the shell itself must be written by a human.

This includes, but is not limited to:

- Documentation
- Installation instructions
- Release notes
- Website content
- User guides
- Examples intended for users

AI may help a contributor understand, research, or brainstorm these materials, but the final user-facing content must be written and reviewed by a human.

The shell itself is excluded from this requirement. AI-assisted code may be used in the shell as long as it follows the rest of this policy.

For example, this file is AI-generated because it is only intended for developers and contributors. However, if the content is something a user who is not a contributor will see, it must be written by a human.

## Keep BCSH Simple

AI should not be used as a reason to make BCSH unnecessarily complicated.

AI-generated code should follow the project's philosophy:

- Keep it simple.
- Keep it small.
- Avoid unnecessary dependencies.
- Avoid unnecessary abstractions.
- Keep the code readable.
- Keep the project easy to modify.

A shorter, simpler solution is generally preferred over a complicated solution that was generated by AI.

## No Blind AI Commits

Do not submit AI-generated code without reviewing it.

Do not assume that code is correct because an AI says it is correct.

Before submitting AI-assisted changes:

1. Read the code.
2. Understand the code.
3. Review the code for unnecessary complexity.
4. Test the code yourself.
5. Run the appropriate automated tests.
6. Fix anything that does not work as expected.

## Summary

**AI is allowed.**

**Human review is required.**

**Human testing is required.**

**User-facing content outside of the shell must be written by a human.**

**The person submitting the code is responsible for the code.**

AI is a development tool, not a replacement for human judgment.
